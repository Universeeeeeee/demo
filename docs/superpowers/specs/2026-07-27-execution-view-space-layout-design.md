# 运行页预览空间重排设计

> 日期：2026-07-27
> 状态：已确认，待实施计划
> 范围：跑步机步态与跑步测试的运行页

## 1. 背景与目标

当前运行页在相机、倒计时和足迹预览下方持续显示“当前未完成周期”和“已完成周期”表格。已完成周期表格最多占用约 170px 高度，导致运行中最需要观察的相机画面、剩余时间和足迹通道偏小。

本次调整的目标是：

1. 从运行页移除已完成周期标题和表格。
2. 将释放的高度优先分配给相机、倒计时和足迹预览。
3. 相机画面始终保持精确 16:9，不拉伸、不裁切。
4. 只有相机达到当前列宽允许的最大 16:9 尺寸后仍有足够空间，才显示大尺寸当前周期摘要。
5. 以 1920×1080 全屏为主要验收场景；较小窗口允许隐藏当前周期摘要。

完整周期仍由算法正常生成并进入统计、报告、导出和历史记录。本设计只改变运行页的信息层级，取代 `plan.md` 中“运行页同时显示当前未完成周期状态和已完成周期列表”的显示要求，不改变周期数据语义。

## 2. 已确认的布局

顶部状态栏、四张指标卡、相机选择按钮和侧栏保持不变。指标卡下方的运行区域维持三列结构：

1. **相机列**：继续使用主要横向空间，列内改为“最大 16:9 相机 + 可选当前周期摘要”的纵向布局。
2. **倒计时列**：固定 72px 宽，贯穿整个运行区域高度。
3. **足迹列**：继续使用次要横向空间，足迹绘图区获得新增高度，暂停和结束按钮固定在底部。

相机列与足迹列继续保持当前约 3:1 的横向伸缩关系。当前周期摘要只占用相机列下方空间，不截短倒计时列和足迹列。

“已完成周期”标签、表格、滚动行为及其专用样式从运行页删除。

## 3. 相机与摘要的空间规则

空间分配必须先满足最大相机，再决定是否显示摘要，不能通过缩小相机换取摘要。

布局根据实际可用几何尺寸计算，不直接判断屏幕分辨率：

1. 根据相机列当前宽度计算该宽度可容纳的最大 16:9 相机高度。
2. 当前运行区域高度能够同时容纳最大相机、10px 间距和 72px 摘要栏时，显示摘要。
3. 空间不足时隐藏摘要，相机继续使用该列可容纳的最大 16:9 尺寸。
4. 窗口尺寸变化时重新计算可见性；摘要的显示或隐藏不能改变相机列宽，因此不应产生反复闪烁。

1920×1080 全屏下必须同时满足最大相机和 72px 摘要栏。较小窗口只保证最大相机、倒计时和足迹预览，摘要可以隐藏。

相机继续复用 `EmbeddedCameraPanel` 现有的精确 16:9 容器。不得改变相机采集、缩放或裁切策略。

## 4. 当前周期摘要

采用已确认的 A 方案：相机下方的一条大尺寸摘要栏。

摘要栏固定高 72px，内部为三个横向信息区：

1. 左侧为主要状态区，小标题显示“当前周期”，大字号显示当前支撑状态，例如“右脚单支撑”。
2. 中间显示左脚当前阶段及时间，例如“左脚　摆动相 0.545 s”。
3. 右侧显示右脚当前阶段及时间，例如“右脚　支撑相 0.190 s”。

主要状态必须明显大于辅助时间信息，保证测试过程中可以快速扫读。内容保持单行，不允许因自动换行增高摘要栏。

尚未检测到有效状态时，主要状态显示“等待触地事件”，左右时间显示 `--`。时间字段为 `None` 或尚未形成时也显示 `--`，不得显示为 `0`。

摘要继续由现有约 10Hz 的步态快照驱动，只显示正在形成的周期状态，不把临时状态写入正式统计、报告或导出。

## 5. 倒计时条

倒计时列固定 72px 宽并贯穿运行区域全高。视觉表现采用方案 B/C 中较充分的横向填充方式：

1. 进度槽占满倒计时列可用高度。
2. 进度控件占满 72px 列宽，不设置额外横向内边距；彩色进度块填满扣除 1px 边框后的内部宽度，不能在宽槽中显示成细竖线。
3. 彩色进度块的纵向长度表示剩余时间比例，并从底部向上填充。例如剩余 `00:42 / 01:00` 时显示约 70% 高度。
4. “剩余”和时间数字始终居中覆盖在进度条上。

倒计时的计算、暂停和恢复行为保持现状。本次只调整空间与视觉填充，不修改计时语义，并保留当前工作区中“暂停时停止倒计时”的既有未提交修改。

## 6. 组件与数据边界

本次只调整 `ui/views/execution_view.py` 的运行页布局和对应测试：

- `EmbeddedCameraPanel` 继续负责相机预览和 16:9 画面约束。
- `FootprintChannelWidget` 继续负责足迹绘制，不改变其数据输入。
- `ExecutionView.on_gait_snapshot()` 继续接收相同快照并更新指标和当前周期摘要。
- 已完成周期数据可以继续出现在快照中，但运行页不再创建、追加或滚动已完成周期表格。
- 步态引擎、周期计算、报告快照、Excel 导出和历史记录不在本次修改范围内。
- 纵跳模式的图表、横向进度条和控制栏布局必须保持不变。

不为一次性布局调整新增跨文件抽象。自适应可见性应封装为 `ExecutionView` 内部的单一布局更新方法，并由尺寸变化触发。

## 7. 异常与边界状态

- 没有步态快照时，摘要保持“等待触地事件”状态。
- 快照中缺少某侧或某个阶段时间时，仅对应位置显示 `--`，其他有效内容继续显示。
- 手动停止模式没有倒计时时，倒计时列继续按现有规则隐藏；相机与足迹列使用释放的横向空间，不保留空白占位。
- 摘要显隐只由可用空间决定，不受是否已经形成已完成周期影响。
- 页面在运行中调整大小时不得导致相机比例失真、控件重叠或摘要反复闪烁。

## 8. 验收与测试

### 8.1 自动化测试

更新 `tests/test_execution_view_footprint.py`，覆盖：

1. 跑步机模式不再包含或显示已完成周期表格。
2. 快照包含已完成周期数据时仍能正常更新指标和当前周期摘要。
3. 1920×1080 全屏对应的执行页可用尺寸下，摘要可见，相机内部预览保持精确 16:9。
4. 较小窗口下摘要隐藏，相机仍保持精确 16:9。
5. 倒计时容器与运行区域等高、宽度为 72px，进度控件填满容器内宽。
6. 足迹区与倒计时使用新增高度，暂停和结束按钮仍在足迹列底部。
7. 当前阶段时间缺失时显示 `--`。
8. 纵跳模式原有图表、横向进度条和按钮方向不变。

执行与运行页相关的 Qt 测试，并至少运行：

```bash
pytest tests/test_execution_view_footprint.py
pytest tests/test_embedded_camera_panel.py
```

### 8.2 视觉验收

在 1920×1080 全屏下确认：

- 已完成周期标题和表格完全消失。
- 相机在当前列宽下达到最大 16:9 尺寸，无拉伸、无裁切。
- 当前周期摘要可见且能在测试距离下快速读出主要状态和左右阶段时间。
- 倒计时槽贯穿主区域，彩色块横向填充充分，纵向比例与剩余时间一致。
- 足迹通道明显高于调整前，暂停和结束按钮位置稳定。

再缩小窗口确认摘要会隐藏，且其余三块内容没有重叠或比例异常。

## 9. 非目标

- 不在运行页增加已完成周期的折叠入口或弹窗。
- 不重新设计顶部指标卡、侧栏或相机设置。
- 不改变步态周期计算、过滤、左右脚映射或不对称率。
- 不改变报告页和历史结果页的周期明细。
