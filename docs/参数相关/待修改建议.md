## 纵跳事件边界回填（当前准则）

> 离线验证过程见：`docs/步态参数相关/纵跳计时误差诊断与方案验证.md`。
> 若本文旧版本或其他计划仍写成“touch/lift 统一候选起点回填”，以本节为准。

### 背景问题

当前纵跳模式下，`SingleFootDetector` 连续 `confirm_samples` 帧满足条件后才触发事件，并把确认成功帧时间作为 `FootEvent.time`。这保证了事件可靠性，但统计用时间戳可能偏离真实光学边界。

当前 `Jump Test` 的关键事实：

- touch 确认依赖有效主簇达到较高阈值：`touch_ratio_threshold=0.12`，且主簇长度必须 `>=10 LED`。
- lift 表面上有 `ratio <= 0.05 or cluster is None`，但由于 `<10 LED` 会被 `_extract_primary_cluster()` 过滤，实际近似为“连续 2 帧没有长度 `>=10 LED` 的有效主簇”。
- session5 诊断显示“边界记录 + 事件确认”方向可能降低误差，但它只是一组探索数据，不能直接作为生产改造依据。

### 核心原则

不要实现两个彼此独立的检测器。更合理的结构是在 `SingleFootDetector` 中每帧只做一次原始簇提取：

```text
bits
  -> raw_clusters(min_length=1)
       -> raw track：维护候选接触轨迹和边界时间
       -> confirm_cluster：从 raw_clusters 中按当前生产规则筛选主簇
```

其中：

- `confirm_cluster` 仍是唯一事件确认依据；
- `raw track` 不单独输出 touch/lift；
- 高阈值确认后，才用与确认簇关联的原始轨迹回填统计边界；
- `FootEvent.time` 表示统计用边界时间；
- `FootEvent.confirm_time` 表示确认成功帧时间；
- 可额外保留 `first_confirm_frame_time` 用于分析 `confirm_samples` 延迟。

### Touch 与 lift 语义不对称

touch 和 lift 不能统一写成“动作起点回填”。

| 事件 | 第一阶段统计边界 | 说明 |
|---|---|---|
| touch | 与确认触地簇属于同一轨迹的 `first_seen_time` | 触地是从无遮挡到首次可可靠关联的遮挡簇 |
| lift | 在当前生产确认语义成立前，同一 active contact track 的 `last_seen_time` | 离地边界是最后一次仍可可靠关联到接触轨迹的原始遮挡 |

第一阶段只做边界回填，不升级 lift 确认规则。举例：

```text
12 LED -> 0 -> 5 LED -> 3 LED -> 0 -> 0
```

在当前生产语义下，`5 LED` 仍会被视为 `cluster is None`，因此可能已经完成 lift 确认。此时不能为了把后续 `3 LED` 纳入同一次接触而暗中改变确认机制。

如果后续离线结果显示 lift 仍有系统性偏差，再单独验证“基于 active raw track 消失来确认 lift”的方案。该方案属于确认语义升级，不能和本阶段边界回填混在同一次生产改造中。

### 时空关联轨迹回填

回填目标不是“找到窗口内最早 1 LED 帧”，而是找到与确认簇属于同一连续接触轨迹的原始观测。

原因：

- 早期 `1 LED` 可能只是孤立噪声；
- 真实接触过程可能有短暂掉帧，不能要求逐帧绝对连续；
- 首次有效观测不一定是 `1 LED`，可能直接从 `0 LED` 到 `3/6/12 LED`。

轨迹关联规则应先在离线工具中实现并记录：

1. 每帧枚举 active tracks 与 raw clusters 的所有可匹配对。
2. 匹配采用一对一分配：一个 raw cluster 最多匹配一条 track，一条 active track 最多接收一个 raw cluster。
3. 使用稳定贪心评分即可，评分至少考虑区间重叠、边缘间距、质心距离、miss 帧数。
4. `1 LED` raw cluster 不允许只靠质心距离接入确认轨迹；它必须满足区间重叠、边缘接近，或在相邻帧持续出现。
5. 允许短暂掉帧，但必须有 `max_missing_frames` 和 `candidate_to_confirm_ms` 约束或诊断输出，避免把很早的噪声接入事件。

实验候选参数不是生产常量，先做敏感性比较：

| 参数 | 候选值 |
|---|---|
| `max_missing_frames` | `0 / 1 / 2` |
| `max_edge_gap_led` | `1 / 2 / 4` |
| `max_centroid_shift_led` | `3 / 5 / 6` |
| `max_touch_candidate_age_ms` | 仅记录 / `20 / 40 / 80` |

“空间距离很远”的阈值不能先拍脑袋写死。先输出每次事件的 `candidate_to_confirm_ms`、候选簇长度、候选簇位置、确认簇位置、匹配分数和 fallback 原因，再根据真实分布决定生产阈值。

### 离线验证方案

先更新 `tools/jump_timing_diagnostics.py`，不要立即改生产链路。

| 版本 | Touch 时间 | Lift 时间 | 目的 |
|---|---|---|---|
| A 当前基线 | 确认成功帧 | 确认成功帧 | 复现当前程序行为 |
| B 确认补偿 | 首个满足当前确认条件帧 | 首个满足当前确认条件帧 | 分离 `confirm_samples` 延迟 |
| C touch-only | 关联轨迹 `first_seen` | B 或当前口径 | 判断 touch 回填贡献 |
| D lift-only | B 或当前口径 | 当前确认语义下的关联轨迹 `last_seen` | 判断 lift 回填贡献 |
| E both | 关联轨迹 `first_seen` | 当前确认语义下的关联轨迹 `last_seen` | 判断组合效果 |

朴素“最近连续原始簇回填”可以作为诊断对照，但不作为生产候选。

### 验收方式

生产改造最低门槛：

1. 至少 3 个独立采集 session。
2. 至少覆盖 15~20 个已匹配完整跳跃。
3. 每个 session 单独计算 MAE，不能只汇总池化。
4. 主指标为 `contact_time MAE`、`air_time MAE`、漏检数、误检数、事件配对失败数。
5. `jump_height MAE` 仅作为 `air_time` 派生影响观察；除非跳高来自独立参考设备，否则不作为独立证据。
6. C/D/E 在多数 session 上不劣于 A，且不增加漏检、误检或配对失败。
7. `fallback_rate` 必须为 0，或有明确、可解释的例外。频繁 fallback 说明轨迹更新顺序、匹配规则或 split/merge 语义仍有问题，不能默默回退掩盖。

### 生产改造边界

离线验证通过后，生产第一阶段只改 `SingleFootDetector`：

- 增加有界 active raw tracks；
- 增加 pending touch candidate / active contact track summary；
- 生产环境只保存摘要字段，不保存完整 `history`；
- 完整轨迹 history 仅存在于离线诊断或 debug ring buffer；
- 不增加 UI 算法开关；
- 不改 `GaitEngine` 统计层、UI、`ReportView` 或 `TestReport` 结构，除非 `FootEvent` 字段扩展需要最小适配。
