# 跑步机模式参数汇总

本文依据 `OptpJump说明书.pdf` 中的 Treadmill Running Test、Treadmill Gait Test、Run Data 和 Gait Data 相关章节整理。

## 参数口径

这里的“参数”分为两类，不能混用：

| 类型 | 含义 | 示例 |
| --- | --- | --- |
| 测试前配置参数 | 测试开始前由操作者设置，或用于采集、过滤、计算逻辑的输入条件。 | 跑步机速度、跑步/行走方向相对接口鼓的位置、最小接触时间、最小腾空时间、足长过滤、自动数据筛选。 |
| 测试后结果参数 | 测试采集完成后，由光栅事件和配置条件计算得到的结果列。 | 步长、步幅、接触时间、腾空时间、步频、支撑相、摆动相、双支撑期。 |

说明书将跑步机模式拆成两个独立测试定义：

| 模式 | 说明书章节 | 定位 |
| --- | --- | --- |
| Treadmill Gait Test | 4.2.2.6, p.70 | 跑步机步态/走路测试。 |
| Treadmill Running Test | 4.2.2.5, p.69 | 跑步机跑步测试。 |

两者都依赖人工填写的跑步机速度。说明书表述为填写 treadmill 设定速度，BioFeedback 章节也要求填写与跑步机实际设置相同的速度；因此在 Iron_Jump 中应先把 `treadmill_speed` 设计为外部人工输入元数据，单位为 `km/h`，不假设能从跑步机控制器自动读取。

说明书中的 `Direction` 不是普通地面步态的进入方向，也不是设备左右方向，而是**受试者跑步/行走方向相对接口鼓（interface drums）的位置**：方向值为 `Interface side` 或 `Opposite side`。说明书给出的规则是：如果接口鼓在跑步机末端，选择 `Opposite side`；反之选择 `Interface side`。因此 Iron_Jump 字段统一为 `direction`，UI 可显示为说明书原名 `Direction`。

配置字段名与 `Iron_parameters.json` / Pydantic 结构保持一致，字段名本身不带单位后缀；单位必须写入 schema 或 Field 描述中。结果字段可以继续使用单位后缀，例如 `contact_time_s`、`step_length_cm`。

另外，说明书指出足长测量对 treadmill tests 是必要的，并且可靠测量只适用于 1 cm 分辨率版本；3 cm 分辨率版本足长误差较大。

## gait: Treadmill Gait Test

### 测试前配置参数

| Iron_Jump 建议字段 | 说明书参数 | 取值 / 范围 | 说明 |
| --- | --- | --- | --- |
| `test_type` | Treadmill Gait Test | `Treadmill Gait Test` | 跑步机步态/走路测试类型；内部 processor/report_type 可再映射为 `treadmill_gait`。 |
| `start_type` | Start type | `Software command` | 只能由软件命令启动；这是固定项，可不作为用户可编辑配置暴露。 |
| `stop_type` | Stop type | `Software command` / `End of Time` | 可由软件命令停止，或到达预设测试时长后停止。 |
| `test_length` | Test length | `mm:ss` 字符串，`00:01-59:59` | 仅当 `stop_type = End of Time` 时需要；算法层可换算为秒。 |
| `treadmill_speed` | Treadmill speed | `0.1-20.0 km/h`，步进 `0.1` | 操作者手工填写跑步机设定速度。 |
| `direction` | Direction | `Interface side` / `Opposite side` | 受试者行走方向相对接口鼓的位置。接口鼓在跑步机末端时选 `Opposite side`；反之选 `Interface side`。 |
| `min_contact_time` | Minimum contact time | 毫秒 `ms` | 小于该阈值的接触时间可被视为无效或并入相邻时间。 |
| `min_flight_time` | Minimum flight time | 毫秒 `ms` | 小于该阈值的腾空时间可被视为无效或并入相邻时间。 |
| `max_flight_time` | Maximum flight time | 毫秒 `ms` | 大于该阈值的腾空时间可被视为无效。 |
| `step_length_calculation` | Step length calculation | `Tip-to-Tip` / `Heel-to-Heel` | 步长按前后两脚脚尖距离或脚跟距离计算。 |
| `min_step_length` | Minimum step length | 厘米 `cm` | 跑步机步态测试专用的最小步长过滤参数。注意这里不是 `Minimum gap between feet`。 |
| `min_foot_length` | Minimum foot length | 厘米 `cm` | 最小足长过滤参数，用于过滤错误采集。 |
| `filter_gaitr_in` | Filter GaitR IN | LED 数 | 进入接触状态时的 GaitR 滤波阈值。 |
| `filter_gaitr_out` | Filter GaitR OUT | LED 数 | 离开接触状态时的 GaitR 滤波阈值。 |
| `automatic_data_filter` | Automatic Data Filter | 关闭或 `10-90%` | 步态测试专用。启用后检查 flight time、contact time、gait time、swing time、step length 是否超出平均值上下指定百分比；超范围行从均值统计中排除，并在表格中以删除线显示。 |
| `starting_foot_override` | Starting foot override | `left` / `right` / 空 | 可选人工覆盖项。实际起始脚应在 START 后由运行时解析并写入会话结果；测试完成后也允许人工修正。 |

### 测试后结果参数

Treadmill Gait Test 的核心结果是 Gait Data。说明书也说明跑步/步态类测试的数值表会分成 Run Data 和 Gait Data 两页；走路模式应以 Gait Data 为主要统计口径。

| 英文结果参数 | 中文名称 | 说明 |
| --- | --- | --- |
| `TExt. [s]` | 外部时间 | 仅外部脉冲可用；软件命令启动的跑步机模式通常不依赖该列。 |
| `Stance phase [s | %]` | 支撑相 | 同一脚从足跟接触到足尖离地的承重支撑阶段，可用秒和步态周期百分比表示。 |
| `Swing Phase [s | %]` | 摆动相 | 同一脚从足尖离地到下一次足跟接触的腾空摆动阶段，可用秒和周期百分比表示。 |
| `Single Sup. [s | %]` | 单支撑期 | 只有一只脚接触地面的时间；一侧单支撑对应对侧摆动时间。 |
| `Total Double Sup [s | %]` | 总双支撑期 | 两个双支撑阶段 DS1 和 DS2 的总和。 |
| `Step Time [s | %]` | 步时间 | 一只脚首次接触到对侧脚首次接触之间的时间。 |
| `Load Response [s | %]` | 负荷反应期 | 第一个双支撑阶段 DS1。 |
| `Pre Swing [s | %]` | 摆动前期 | 第二个双支撑阶段 DS2。 |
| `Step Length [cm]` | 步长 | 一侧脚落地点到对侧脚落地点之间的距离。 |
| `Gait cycle [s]` | 步态周期 | 同一脚连续两次首次接触之间的时间。 |
| `Stride Length [cm]` | 步幅 | 同一脚连续两次落地点之间的距离。 |
| `Speed [m/s]` | 速度 | 单步平均速度。 |
| `Accel. [m/s2]` | 加速度 | 前两步速度变化量。 |
| `Cadence [step/s]` | 步频 | 单位时间内的步数。 |
| `Total dist. [cm]` | 总距离 | 受试者累计行走/跑动距离。 |
| `Contact Phase [s | %]` | 着地相 | 从足跟首次接触到全足支撑的时间，也可表示为接触时间百分比。 |
| `Foot Flat [s | %]` | 全足支撑期 | 足部完全接触地面的时间，也可表示为接触时间百分比。 |
| `Propulsive phase [s | %]` | 推进相 | 从足跟抬起到足尖完全离地的时间，也可表示为接触时间百分比。 |

### 测试后结果参数

Treadmill Running Test 的核心结果是 Run Data。说明书还提到 Run Test 在模块系统或跑步机上可查看 Run Report，用于关注左右脚不对称性。

| 英文结果参数 | 中文名称 | 说明 |
| --- | --- | --- |
| `TExt. [s]` | 外部时间 | 仅外部脉冲可用；软件命令启动的跑步机模式通常不依赖该列。 |
| `Time [s]` | 累计时间 | 从测试开始计算的渐进时间。 |
| `Distance [cm]` | 累计距离 | 受试者累计行走/跑动距离。 |
| `TCont. [s]` | 接触时间 | 足部接触地面的时间。 |
| `TFlight [s]` | 腾空时间 | 两次接触之间的腾空时间。 |
| `Height [cm or in]` | 腾空时间推算高度 | 根据腾空时间估算的高度派生量。内部字段建议命名为 `flight_time_derived_height_cm`，不要与 IMU、测力台或动捕得到的真实质心轨迹混用。 |
| `Speed [m/s or ft/s]` | 速度 | 单步平均速度。 |
| `Accelerations [m/s2 or ft/s2]` | 加速度 | 前两步速度变化量。 |
| `Steps [cm or ft]` | 步长 | 一侧脚落地点到对侧脚落地点之间的距离。 |
| `Stride [cm]` | 步幅 | 同一脚连续两次落地点之间的距离。 |
| `Pace [step/s]` | 步频 / 节奏 | 单位时间内的步数。 |
| `Stride angle [deg]` | 步幅角 / Alpha 角 | 步幅抛物线切线角。 |
| `Imb. [%]` | 不平衡指数 | 左右脚之间的跑步不对称性指标。 |
| `Double Sup [s]` | 双支撑期 | 两脚同时接触地面的时间。跑步时该值可能很小或不存在，但结果列仍属于说明书定义。 |
| `Step Times [s]` | 步时间 | 一只脚首次接触到对侧脚首次接触之间的时间。 |
| `Contact Phase [s | %]` | 着地相 | 从足跟首次接触到全足支撑的时间，也可表示为接触时间百分比。 |
| `Foot Flat [s | %]` | 全足支撑期 | 足部完全接触地面的时间，也可表示为接触时间百分比。 |
| `Propulsive phase [s | %]` | 推进相 | 从足跟抬起到足尖完全离地的时间，也可表示为接触时间百分比。 |

## 运动员与会话输入

`min_foot_length` 是算法过滤阈值，单位为 `cm`，不等于受试者实际足长。说明书中的 `Capture foot` 会把足部遮挡 LED 数换算为厘米并保存到运动员档案；跑步机测试应同时保留长期档案值和本次测试快照。

| 层级 | 建议字段 | 说明 |
| --- | --- | --- |
| 运动员档案 | `measured_foot_length_cm` | 通过 `Capture foot` 或人工录入得到的受试者足长。 |
| 测试会话 | `foot_length_cm_snapshot` | 本次测试开始时冻结的足长快照，用于保证历史结果可复算。 |
| 测试会话 | `foot_length_source` | 足长来源，例如 `captured`、`manual`、`unknown`。 |

## 会话运行状态与结果元数据

跑步机模式的起始脚不应只作为测试前配置。说明书中，START 后首先触地的脚会被解析为起始脚；如果 START 发生在双支撑期，则跑步机前方的脚为起始脚；测试后还可以人工修正。

| 建议字段 | 取值示例 | 说明 |
| --- | --- | --- |
| `resolved_starting_foot` | `left` / `right` / `unknown` | 本次测试最终采用的起始脚。 |
| `starting_foot_source` | `auto_first_contact` / `auto_double_support_front` / `manual_override` / `manual_correction` | 起始脚来源，用于区分自动判定、配置覆盖和测试后修正。 |
| `suspension_segments` | 时间段列表或空 | 跑步机类型测试可能出现 Suspended 状态；若当前 MVP 不实现暂停/恢复，可先置空，但不要把暂停时间混入有效统计。 |

## 逐步有效性与统计纳入状态

说明书中存在多种行状态和无效时间管理逻辑，包括 `Deleted`、`Tc not valid`、`Tf not valid`、`No step`、`Suspended` 等。自动数据过滤也会把超出范围的步从均值统计中排除。每一步/每跨步结果应保留其有效性和统计纳入状态，避免只看到均值变化而无法追溯原因。

| 建议字段 | 取值示例 | 说明 |
| --- | --- | --- |
| `step_side` | `left` / `right` / `unknown` | 当前步或跨步所属侧。 |
| `row_status` | `valid` / `deleted` / `tc_not_valid` / `tf_not_valid` / `no_step` / `suspended` / `split` / `external` | 对齐说明书的结果行状态。 |
| `is_event_valid` | `true` / `false` | 原始事件是否通过阈值和状态校验。 |
| `is_included_in_statistics` | `true` / `false` | 当前行是否纳入平均值、标准差、CV 等统计。 |
| `event_invalid_reason` | 字符串或空 | 事件无效原因，例如接触时间过短、腾空时间过短、无有效步。 |
| `statistics_exclusion_reason` | 字符串或空 | 未纳入统计的原因，例如自动数据过滤、手动删除、暂停段。 |
| `correction_source` | `none` / `threshold_filter` / `automatic_data_filter` / `manual_delete_row` / `manual_delete_contact` / `manual_delete_flight` / `manual_restore` | 数据修正来源。 |

## 汇总统计层

说明书在结果表底部给出最小值、最大值、平均值、标准差和变异系数 CV；部分测试还会按左右脚分别计算。报告层建议使用通用结构保存每个指标的汇总，不要为每个指标复制一套字段。

```python
@dataclass(frozen=True)
class MetricSummary:
    count: int
    mean: float | None
    min: float | None
    max: float | None
    std: float | None
    cv_percent: float | None
```

| 报告层字段 | 说明 |
| --- | --- |
| `per_step_results` | 每步/每跨步明细结果，包含有效性、侧别和统计纳入状态。 |
| `left_right_results` | 左右脚拆分后的结果集合。 |
| `metric_summaries` | 各指标的 `MetricSummary` 汇总。 |
| `asymmetry_metrics` | 左右侧不对称性相关指标，例如 Run Report 所关注的指标。 |
| `report_config_snapshot` | 生成报告时使用的配置快照，便于复算和解释历史结果。 |

## 不纳入当前 MVP 的范围

以下能力不属于纯光栅跑步机模式的核心测试配置，当前可不纳入：

| 能力 | 处理建议 |
| --- | --- |
| Metronome | 作为独立 `MetronomeConfig`，不进入跑步机核心配置。 |
| Video / second-monitor feedback | 作为 `FeedbackConfig` 或 UI 展示配置，不进入核心算法配置。 |
| BioFeedback 脚交换和声音提示 | 属于独立训练工具模式，不进入正式测试链路。 |
| 心率 | 属于独立外设模块。 |
| Gyko / IMU 指标 | 明确排除，包括躯干 AP/ML 摆动、RMS、Harmonic Ratio、UPCI、动态稳定性等。 |

## 实现注意事项

1. `Treadmill Gait Test` 和 `Treadmill Running Test` 应作为独立 `test_type`，不要只复用普通地面步态模式；内部 processor/report_type 可再映射为 `treadmill_gait` / `treadmill_running`。
2. `test_length` 只在 `stop_type = End of Time` 时必填，格式为 `mm:ss`；软件命令停止时可以为空。算法层需要时再换算为秒。
3. `Treadmill Gait Test` 使用 `min_step_length`，单位为 `cm`；`Treadmill Running Test` 使用 `min_gap_between_feet`，单位为 `cm`，两者不要混淆。
4. `automatic_data_filter` 是 `Treadmill Gait Test` 专用配置，单位为 `%`，不应默认套到 running。
5. 起始脚支持自动推断、人工覆盖和测试后修正；最终值应保存到 `resolved_starting_foot`，来源保存到 `starting_foot_source`。
6. 跑步机速度先作为人工输入元数据保存；除非后续硬件明确提供控制器接口，不要假设自动同步速度。
7. `min_foot_length` 与 `foot_length_cm_snapshot` 语义不同：前者是过滤阈值，单位为 `cm`；后者是本次测试采用的受试者足长快照。
8. 每步结果需要保存 `row_status` 与 `is_included_in_statistics`，否则报告中的均值、标准差和 CV 缺乏可追溯依据。
